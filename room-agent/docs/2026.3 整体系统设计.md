# 整体系统设计

## 1. 系统架构

### 1.1 文字版架构图（Mermaid）

```mermaid
flowchart LR
	Sensor((传感器事件)) --> Trigger
	Agent((Agent 事件)) --> Trigger

	subgraph RuleEngine[规则引擎]
		Trigger{触发推理?}
		Auto[自动化引擎]
		ExecRule[执行]
		Trigger --> Auto --> ExecRule
	end

	Trigger --> LLMAvail{LLM 可用?}

	subgraph Degrade[优雅降级链路]
		TradIntent[传统意图识别]
		ExecDegrade[执行]
		TradIntent --> ExecDegrade
	end

	subgraph LLMFlow[LLM 工作流]
		Intent{意图识别}
		ToolSelect[工具选择]
		DirectReply[直接回复]
		Reasoner[工具 / 文本推理输出\n(含工具列表)]
		HumanAudit{可选人类审计?}
		ExecLLM[执行]

		Intent -->|有工具调用| ToolSelect --> Reasoner --> HumanAudit --> ExecLLM
		Intent -->|无工具调用| DirectReply
	end

	LLMAvail -->|N| TradIntent
	LLMAvail -->|Y| Intent
```

### 1.2 流程说明

1. 输入事件层
- 输入源包含两类：传感器事件、Agent 事件。
- 事件首先进入“触发推理”节点。

2. 确定性主链路（规则引擎）
- 触发推理后进入自动化引擎。
- 自动化引擎产生确定性执行动作。

3. LLM 可用性分流
- 在触发推理后并行判断“LLM 是否可用”。
- 不可用（N）时，进入优雅降级链路。
- 可用（Y）时，进入 LLM 工作流。

4. 优雅降级链路（LLM 不可用）
- 采用传统意图识别。
- 识别后进入执行，保证基础能力可用。

5. LLM 工作流（LLM 可用）
- 先做意图识别。
- 若无工具调用需求，直接回复。
- 若有工具调用需求，进入工具选择，再进入“工具/文本推理输出”。
- 输出阶段可携带可用工具列表。
- 推理结果可选接入“人类审计”，审计后再执行。

### 1.3 颜色语义（与原图对应）

- 蓝色：确定性流程（规则引擎、执行等）
- 绿色：低成本 LLM 节点（意图识别、工具选择、直接回复）
- 粉色：较强 LLM 节点（工具/文本推理输出）

### 1.4 备注

- 若出现差异型事件，需提供设备状态的时序存储能力，或下沉到下层模块处理。

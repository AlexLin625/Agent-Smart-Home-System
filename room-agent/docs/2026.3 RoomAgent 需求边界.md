# 2026.3 RoomAgent 需求边界

房间级智能体模块需求边界整理（PoC）

目的：记录当前已确认的设计约束、尚未确认的问题，以及后续需要继续澄清的边界条件。

## 一、项目背景

该模块属于本科毕业设计的一部分，实现目标为概念验证（Proof of Concept）。

约束：

- 不要求生产级完整性
- 需要保持一定流程可靠性
- 架构应允许未来迁移到本地小模型运行环境
- 模块职责限定在房间级智能体

系统整体存在多层控制结构，本模块仅负责房间级局部自治与控制。

## 二、总体设计原则（已确认）

1. 确定性逻辑优先
- 事件触发
- 简单自动化
- 状态聚合

2. 引入大模型参与系统决策
- 但不作为唯一控制逻辑

3. 两部分系统：确定性 + LLM 接入

确定性系统：

- 事件处理
- 状态更新
- 自动化规则
- 动作校验

大模型系统：

- NLP / 意图理解
- 边界模糊场景辅助决策
- 规则管理辅助

4. 未来兼容小模型（< 70B）迁移

因此系统需要：

- 结构化输入
- 受约束动作输出
- 避免无限制生成式控制

## 三、模块核心职责（已确认）

房间级智能体负责：

1. 聚合多源输入
- 传感器（来源于设备接口）
- 上层智能体指令

2. 构建统一 Room State

Room State 作为：

- 房间状态唯一可信源
- 局部决策依据

3. 执行局部自动化

包括：

- 条件触发动作
- 房间模式切换
- 状态上报
- 异常上报

## 四、明确不在范围内的内容

PoC 阶段不覆盖：

- 跨房间协同
- 全局资源调度
- 长期规划
- 多步复杂任务编排
- 多用户偏好冲突
- 复杂学习或个性化建模
- 生产级容灾

核心输入来源：

实验阶段：

- 沙盘环境预计只有 1~2 个传感器

- 设备状态轮询变化

需要确定哪些属于正式触发源。

## 六、房间级权限边界（已确认）

房间级智能体只负责：

- 本房间控制域内设备

约束：

- 不直接控制跨房间资源
- 不直接控制全局系统
- 上层指令优先级更高

房间级智能体职责：

- 执行
- 局部细化

而非推翻上层目标。

## 七、Room State 模型

已确认

Room State 包含：

1. 当前事实状态
2. 历史记录

状态来源：

- 设备接口
- 传感器
- 上层输入

当前版本：

- 状态建模为确定性状态
- 不引入概率或不确定性模型

状态真值原则

系统无法直接观测物理真实世界。

因此：

设备接口回读作为事实真值来源。

Room State 是：

- 设备状态
- 控制意图
- 传感器输入

的统一抽象。

## 八、自动化能力边界

已确认

系统只需要支持：

1. 条件触发设备动作
2. 房间模式切换
3. 状态 / 异常上报

系统不支持：

- 长期规划
- 多步任务编排
- 复杂任务链

房间模式

模式集合为预定义固定集合。

模式不会由模型动态生成。

待确认

需要定义：

- 模式列表

例如：

- idle
- occupied
- sleep
- away

或其他模式集合。

## 九、执行流程（初步）

事件进入系统

-> 更新 Room State

-> 确定性规则 / 状态机处理

-> 必要时调用大模型

-> 动作校验

-> 执行设备控制

-> 状态 / 异常上报

## 十、可靠性边界

### 10.1 输入前提

系统输入来源：

- 传感器
- 其他智能体

因此默认输入具有一定确定性。

系统不是直接面向终端用户。

### 10.2 状态同步策略

系统以设备接口状态作为观测真值。

Room State 需要周期性同步接口状态。

### 10.3 信息不足处理

当信息不足时：

- 不进行推测
- 直接上报

### 10.4 执行失败处理

执行失败时：

系统需要：

- 上报异常
- 标记失败状态
- 停止当前任务

允许：

- 对简单错误进行有限重试

不要求：

- rollback
- 分布式事务

### 10.5 可观察性

可解释性 / 可观测性：

- 属于非功能性需求
- 可以后续优化

## 十一、状态写入策略

尚未完全确定。

取决于智能家居平台能力。

若支持状态回读：

建议区分：

- command_state
- observed_state

示例：

- command_sent
- waiting_confirm
- command_failed
- observed_on
- observed_off

## 十二、未解决问题清单

以下问题仍需后续确认。

1. 工作流触发源

需要确定系统正式触发源列表。

候选：

- 上层智能体指令
- 定时触发
- 用户手动设备操作
- 设备状态轮询 (本系统的非智能部分负责发出传感器事件)

2. 房间模式集合

需要确定具体模式名称与数量。

3. Lock 作用范围

执行失败后 lock 的粒度：

可能选项：

- 单设备
- 单动作类型
- 单规则
- 整个房间

4. 重试策略

需要确定：

哪些错误允许自动重试。

例如：

- 网络超时
- 网关无响应

哪些错误直接失败上报。

5. Room State 最小字段集

需要确定 Room State 的最小结构。

候选字段：

- device_state
- last_command
- last_update_time
- data_source
- execution_state
- error_flag

进入房间智能体输入。
